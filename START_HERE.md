# Кабінет тренера: перенос из Claude Design

Это подготовленные материалы для учебного переноса прототипа в React + TypeScript + Vite. Готового Vite-приложения в архиве пока нет.

## Что удалось извлечь

- `reference/claude-design-export.html` — оригинальный экспорт без изменений, со встроенными ресурсами и лицензией шрифта.
- `reference/prototype.html.txt` — читаемый шаблон основного компонента. Расширение `.txt` намеренное: это материал для переноса, а не самостоятельная веб-страница.
- `reference/prototype.logic.js` — извлечённая логика основного компонента.
- `reference/design-tokens.json` — основные цвета, шрифт и размеры из экспорта.
- `reference/LICENSE-Manrope.txt` — лицензия шрифта из исходного файла.
- `CLAUDE.md` — правила учебной работы с этим проектом.

Экспорт использует служебный формат Claude Design: `x-dc`, `sc-if`, `sc-for`, выражения `{{ ... }}` и класс `Component extends DCLogic`. Встроенный runtime использует React, однако прикладной код не представлен готовыми компонентами React/TSX. Разметку и логику нужно осмысленно перенести в обычные компоненты; подключать служебный runtime в новое приложение не требуется.

## Подтверждено чтением кода

Проверка выполнена статически: распакованы вложенные ресурсы, прочитаны шаблоны и обработчики. Работа кнопок в браузере в рамках этой проверки не запускалась.

- Клиенты: добавление и редактирование, поиск по имени, активные/неактивные, цена занятия, остаток, формы и ошибки.
- Расписание: выбор дня, создание и перенос занятия, отмена и восстановление, предупреждение о пересечении времени.
- Ближайшая тренировка вычисляется по будущим неотменённым записям расписания.
- Клиенты и занятия хранятся в состоянии компонента. Обращений к `localStorage`, `sessionStorage`, IndexedDB или серверному API в прикладной логике нет.
- Корневой экспорт содержит два iframe фиксированного размера: 1440 × 900 и 390 × 844. Мобильный шаблон импортирует тот же основной компонент с `compact: true`; извлечённая логика совпадает с логикой компьютерной версии. Каждый iframe создаёт собственное состояние.
- «Минуло» вычисляется по прошедшему времени. Это не подтверждение проведения тренировки. Списание занятий и оплаты не реализованы.

## Цель переноса

Сохранить визуальный стиль и существующие сценарии, получить одно адаптивное приложение с общими данными. При изменении ширины окна клиенты и расписание должны сохраняться. Сначала работаем с вымышленными данными на одном компьютере.

Папка `reference/` остаётся справочным материалом. Новое приложение создаём в `app/`, чтобы не смешивать экспорт и исходники.

## Порядок обучения

1. Проверить окружение на компьютере пользователя. Создать React + TypeScript + Vite в `app/`, запустить стартовую страницу и объяснить основные файлы.
2. Перенести оболочку приложения: цвета, Manrope, навигацию и адаптивную сетку. Использовать CSS-медиазапросы и гибкую ширину вместо двух iframe и фиксированных размеров.
3. Перенести клиентов: типы данных, список, фильтры, добавление/редактирование и валидацию. Не менять дизайн без необходимости.
4. Перенести расписание и связь с клиентами. Вынести расчёт пересечений и ближайшего занятия в отдельные чистые функции.
5. Добавить сохранение клиентов и занятий в `localStorage`. Затем проверить поведение после обновления страницы.
6. После этих этапов отдельно спроектировать проведение тренировок, списание занятий и учёт оплат. Сервер и PostgreSQL — дальнейший учебный этап.

Не реализовывать все этапы за один проход. Первый результат — локально открывающийся Vite-проект и понимание его структуры.

## Требования к сохранению

- Хранить версию схемы, клиентов и занятия вместе под отдельным ключом, например `trainer-desk:v1`.
- Читать данные при первоначальной инициализации. Проверять структуру прочитанного JSON и обрабатывать недоступное хранилище/ошибку записи понятным сообщением.
- Создавать демо-данные только при отсутствии сохранённого набора или по явной команде восстановления. Пустые массивы — допустимые сохранённые данные; после очистки и перезагрузки демо не должны появляться снова сами.
- Не перезаписывать повреждённое значение автоматически: дать пользователю возможность явно сбросить его.
- Данные `localStorage` доступны в этом браузере для этого адреса приложения. Это не синхронизация между ноутбуком и телефоном и не резервная копия.

## Что учесть при переносе

- В текущем `openNewS` есть fallback на первого клиента, даже если активных клиентов нет. Для новой записи показывать понятное состояние «добавьте/активируйте клиента», не выбирать неактивного автоматически. При редактировании старой записи сохранить возможность видеть её текущего клиента.
- Проверки даты и времени в исходнике основаны на регулярных выражениях. Дополнительно проверять реальность даты и допустимость времени; определить единый часовой пояс расписания.
- Для одной рабочей зоны тренера ориентир — `Europe/Kyiv`. Не превращать локальную календарную дату в UTC-день через слепое `toISOString().slice(0, 10)`.
- Предупреждение о пересечении должно сохранять смысл явного действия «Зберегти все одно». Для восстановления проверять время именно той записи, которая будет восстановлена.
- Поле `left` означает текущий остаток. В исходной форме оно подписано «Оплачено тренувань»; при переносе уточнить подпись, чтобы не смешивать остаток с историей покупок.
- В обычном CSS можно использовать `:focus-visible`; воспроизводить ограничения дизайнового runtime не требуется. У диалогов нужны Escape, управление фокусом и возврат фокуса к открывшей кнопке.
- «Оплати» остаётся будущим разделом. Не добавлять автоматически оплаты, списания, AI или авторизацию на первом этапе.

## Проверка готовности этапа сохранения

Добавить клиента и занятие → обновить страницу → обе записи остались. Перенести/отменить занятие → ближайшее занятие у клиента обновилось. Изменить ширину окна → данные остались прежними. Очистить демо-данные → обновить страницу → список остаётся пустым. Проверить границы пересечений: окончание одного занятия ровно в момент начала другого не является конфликтом.

Для запуска нового приложения использовать созданные в `app/package.json` команды. Этот архив сам по себе не содержит `package.json` и не запускается через `npm run dev`.
